# Tank X reader

Versioned source of the public-profile Apify worker, imported from build `c99YRMlKXube5V0gV` (0.2.2). `main.py` reads INPUT and writes OUTPUT once. `direct_fetch.py` validates inputs and composes snapshots; `public_profile.py` reads public X profiles without an X session, cookies or a configured proxy.

INPUT accepts `handles`, optional `concurrency` (default 6, maximum 8), `cursors`, and `requestId`. OUTPUT schema version 1 contains `health`, `posts`, `accounts`, `nextCursors`, `failedAccounts`, and `coverageGaps`. Tank owns baseline seeding, durable cursor advancement and item deduplication.

Each post's `text` is the complete post with its links expanded, read from the GraphQL result the signed-out page embeds; the visible HTML, which stops at "Show more", is the fallback. `referencedPosts` lists the posts it quotes, replies to or links (`relation` `quoted`, `replied_to` or `linked`), each with `id`, `author`, `url`, `publishedAt` and `text`. Quoted text is usually on the profile page. For posts above an account's cursor, a missing text is read from that post's signed-out status page, at most 24 per run, sharing the account concurrency, retries and run deadline; an unreadable post keeps `text: null` and an `error` such as `PUBLIC_POST_HTTP_404`, `QUOTED_POST_UNAVAILABLE` or `REFERENCE_FETCH_LIMIT`, and, when requests were made for it, their `diagnostics`. Signed-out profiles list original posts only (`ProfileOriginalsProduct-Timeline`): reposts and replies to other accounts are not visible without an X session.

Each page read (a profile or a referenced post) has at most three attempts: immediately, after 1 second, then after 5 seconds. Every HTTP error status and every transport failure is retried; success stops the sequence. A page that arrives but cannot be used (redirect off X, over 2,000,000 bytes, unparseable) is not requested again. Accounts share a run deadline below the 110-second synchronous API timeout, shortened by `ACTOR_TIMEOUT_AT` when present. Failed accounts retain their cursors.

Failed accounts and unreadable referenced posts include `diagnostics`: the GET method/URL and empty request body, attempt times/outcomes and, for each error response, the status, every header as a `[name, value]` pair in the order received, and the whole body. Nothing is cut: there is no size limit on an error response or on a run's evidence, so a run in which many pages fail with very large bodies is limited only by the run deadline and the actor's memory. A body that could not be read to the end is marked (`bodyTruncated`, `readError`, `omittedWireBytes`). UTF-8 bodies remain text; binary bodies are base64; gzip bodies are decoded. Credential values (the Apify token, bearer tokens, `authorization`, `cookie`, `set-cookie`, `auth_token`, `ct0`) are replaced with `[REDACTED]` in header values and in the body. Tank shows the diagnostics of an HTTP error in its Ops notice, as an attached text file when they do not fit a message.

The existing permanent CI runs `tests/test_x_reader.py` and `tests/test_x_reader_integration.py`, installing this directory's pinned requirements separately from the shipping Tank environment. The integration suite uses isolated real HTTP listeners for profile failures, actor snapshots and Telegram notices; it does not call paid Apify runs or production Telegram.

Tank's Deploy workflow publishes this directory: when its files differ from the actor build tagged `direct`, `scripts/deploy/apify_worker.py` builds them as version 0.3 and moves `direct` to the new build before Tank is rolled, and restores the previous build if Tank rolls back (docs/OPERATIONS.md). Keep the worker and Tank compatible in both directions across one release.
