## Required retained distinctions

Each retained site still needs the concrete justification in its owner's report; a broad label such as wire or historical is insufficient.

- Missing provider/header/usage/cost/provenance values remain unknown when never supplied. Current observations, collection clocks, zero or empty strings must not invent those facts.
- Raw bytes and JSON exist at real input/persistence boundaries. Valid application/domain records use closed models; genuine indexes, headers, cursors and budget histories have concrete keyed value types.
- Optional dependencies are replaced by explicit composition or distinct live/recorded variants. Lifecycle absence, unopened resources and genuinely inapplicable outputs remain explicit variants or precisely justified optional fields.
- Historical invalid numeric text is evidence. Sparse lifecycle writes may record a failure without normalizing that text into a valid quantity.
- Immutable captured modules and oracle recipes are observed and hash-checked, not executed or rewritten to make current code agree. Actual upstream source/comments/licenses remain preserved.
- The constrained guest diagnostic worker is the exact standard-library exception documented in [executable boundaries](executable-boundaries.md); it does not waive strict Pydantic for application code.
