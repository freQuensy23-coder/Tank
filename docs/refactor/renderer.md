# Schema renderer boundary ledger

This ledger covers the whole active `scripts/render_db_schema.py` module and its dedicated tests. It does not cover `diagram_diff.sh`, other deployment/CI scripts, publisher code, or upstream programs. Current PostgreSQL and ClickHouse SVG output remains byte-identical. No database, provider or deployment runs are involved in rendering.

The module has precise parameter/return annotations throughout. Parsed SQL columns, key/check/FK constraints, unique indexes, final rendered tables/columns, ClickHouse schema/backend metadata, native/version/SQL columns, retention rules, route specifications, positioned boxes, measurements and CLI arguments use named strict Pydantic records. Mutable parser state is distinct from immutable rendered facts. No cast, ignore, `Any` annotation or per-module mypy suppression is added.

| Symbol/site | Retained boundary or absence | Meaning and behavior |
| --- | --- | --- |
| `literal_assignments` return values | `dict[str, object]` | Actual Python AST literal admission, before named metadata validation. Keys are requested constant names. Missing constants fail the required metadata model; requested nonliteral or valueless assignments refuse. Source is parsed, never imported or executed. |
| `MarketSchemaMetadata`, `ClickHouseMetadata` mappings | Table, column, SQL-type and identity indexes | Keys are actual dynamic schema identifiers; typed values are validated, and `ClickHouseInputs` verifies referenced partitions/types. No arbitrary domain JSON payload is retained. |
| `ParsedTable.constraints`, `parse_pg.tables/owners`, `finish_pg` and `diff_tables` indexes | SQL-name indexes | SQL declarations and later ALTER/DROP statements address exact names. `pop(..., None)` handles SQL IF EXISTS/removal of an absent declaration; a missing prior table in `diff_tables` is the explicit added-table case. |
| `new_table` empty collections/zero and `new_col` required flags | Declared parser initial state | A newly encountered CREATE TABLE starts without declarations; counters/collections accumulate only observed SQL. The SQL column constructor requires every consumed fact. These are not missing input substitutes. |
| `ParsedTable.storage/note`, `RenderedTable.index_delta/change`, `RenderedColumn` optional markers | Genuine unrequested or absent diagram metadata | No WITH/storage annotation, no explanatory note, unchanged index count, no comparison/highlight, no constraint marker or no illustrative reference remain distinct from a present value. Generated SQL primary-key/check names are deterministic labels for genuinely unnamed SQL declarations. |
| `parse_col_def` default/constraint matching | Optional SQL clauses | A column without DEFAULT or NOT NULL has no sequence flag or explicit nullability; primary keys subsequently impose nullability. The native SQL type is preserved after documented display abbreviation. |
| `statements`, `parse_pg` | Deliberately bounded SQL diagram reader | Function bodies, comments and non-schema migration commands are not executed or rendered. This is not a general SQL validator. Tables/columns/constraints/indexes/trigger identities consumed by the current diagram are parsed. Current migration coverage is checked against the actual committed diagram. |
| `collapse_prec`, `precision_companions` | Timestamp precision presentation | No companion pair means no precision badge; a partial or ambiguous pair refuses. Both real companions are hidden only when the corresponding timestamp owns them. |
| `LOGICAL`, `SPECIFIC`, `REF_TARGET`, `COMPOSITE` | Explicit illustrative-reference lookup tables | These are diagram conventions, separate from actual SQL FK facts. Missing illustrative mapping yields no arrow. Composite/single identity applicability is checked against actual constraints; partial unique indexes cannot authorize unconditional identity. |
| `TRIGGER_FLAGS`, `SCHEMA`, `PG_ROUTES`, `PG_GUTTERS`, `LANES`, layout positions | Authored layout/style indexes | Unknown required trigger/schema/route/gutter/lane keys refuse through lookup. All current gutters are explicit. Lane values preserve the existing spacing divisor, including the existing boundary-positioned route; no new lane-capacity policy is inferred. |
| `RouteSpec.side` | Cross-column routes have no same-column side | Same-column routing requires an explicitly declared side and one lane. Adjacent routes require one lane, multi-column routes two. One-to-one relation markers are explicitly authored booleans. |
| `pg_metrics` absent-reference width, `index_count`, `integrity_gaps` and schema counts | Empty-set reductions and counters | No reference hint requires zero extra text width. Counts start at zero and aggregate actual observed entries; an empty schema displays zero tables. No operational capacity/financial value is inferred. |
| `ClickHouseInputs` codecs and `ch_rows` hints | Declared serialization/display policy | Explicit SQL-kind codec entries override the backend's captured ZSTD codec for remaining validated types. An absent optional hint/reference produces no badge; native and version columns remain distinct variants. |
| `RetentionConfiguration` extra fields | Narrow actual configuration projection | Only the three authoritative integer retention fields are consumed; all three are required, no defaults. Other threshold keys are intentionally unconsumed. Explicit zero is rendered as zero; the renderer adds no negative bound or disable semantics beyond the source policy. |
| `text` optional weight/anchor/style | SVG attribute omission | None omits an unrequested attribute. Supplied attributes are escaped/typed; current SVG formatting is preserved. |
| `pg_model_at`, `render_pg.base_ref`, `RendererArguments.diff` | Optional comparison mode | No ref means current-schema output. A requested real Git ref supplies the actual base migrations; missing/invalid Git data fails. CLI `--diff` requires exactly the ref and output directory. |
| `RendererArguments` root/check/png defaults | Declared CLI interface | argparse's default repository root and opt-in check/PNG booleans are documented choices. Its raw namespace is validated before application use. `--check` reports absent/stale files; ordinary mode writes current SVG and optional PNG. |

Meaningful regression coverage includes composite FK scope, rejected partial/mismatched constraints without installing facts, strict bool/number/missing fields, immutable constraints, invalid geometry, nonexecuted AST metadata, missing/partial precision, unknown SQL-kind mapping, actual changed retention and explicit zero, partial-index identity, independent nullability/sequence diffs, route side/endpoints and exact current SVG bytes. Real `--check` and `--diff 57d11814 <owned external output>` execution also verifies command wiring and PNG conversion. Historical failed authored expectations and the rejected lane-policy experiment are retained externally; neither is passing evidence.
