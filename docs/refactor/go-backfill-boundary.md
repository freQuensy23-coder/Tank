The separate HOT `BackfillAnchors` reader and its partial-order/freshness policy are unchanged.

Duplicate/unknown keys, trailing input, invalid UTF-8 and invalid result JSON refuse at this physical boundary.

Physical decoding preserves nullable/raw text and result JSON; it does not promote malformed retained facts into a valid command. Consumed command identities and recorded aware anchors are admitted separately. Missing/invalid consumed facts become a closed explicit terminal refusal instead of rolling back the selection and repeatedly blocking the queue. A malformed token NULL is preserved as raw evidence, not fabricated into a Python-valid BackfillFailed. Stored unknown source precision is not upgraded to verified T0/T1 or replaced with now. Submicrosecond anchor wire values explicitly refuse before capture rather than being silently rounded to the six-digit result wire representation.

The live result contains named minute/window coverage, actual instrument identities, pre24 reference variants and benchmark observations. COMPLETE/PARTIAL derives from those observations. Failure kinds/reasons are closed, mismatched/unknown variants and zero values refuse, and failures cannot manufacture a new empty result. Pre24 references must be strictly before their declared boundary; equal/future witnesses refuse. Numeric trade identities retain exact integer text; no float conversion is used to admit them. Actual benchmark token identities/symbols are required; absent eligible configured instruments remain the distinct observed no-selection case.

## Actual persistence and lifecycle

`StartBackfill` and `FinishBackfill` lock the selected physical storage key in one transaction, compare its actual xmin observation, rebind command facts to the locked row and return APPLIED/SUPERSEDED/MISSING. APPLIED carries the actual returned new revision only after commit. Missing/stale writes do not resurrect a row, overwrite a newer requeue or claim success. In-memory test revisions witness actual test-store mutations; they are not asserted to be PostgreSQL xmin values.

Start acknowledgment precedes provider capture effects. Completion writes only owned lifecycle fields, current explicit writer metadata and, for an actual captured outcome, the named new result. Lifecycle-only failures preserve the prior result and unconsumed identities/anchor/provenance. Write/commit failure returns an error without acknowledgment; actual trigger-error rollback is tested. Context cancellation after a real start leaves RUNNING retryable and releases in-flight ownership; original same-ID retry/no-concurrent-duplicate and five-second lifecycle oracles remain intact.

Current collection clocks come from the existing microsecond SystemClock; source clocks retain their recorded origin. No default build identity, anchor or worker-start is added. An empty physical storage key can be witnessed and terminally refused without inventing another key.

Semantic fingerprints use a backfill-specific exact JSON document. SQL result text retains integer precision beyond2^53 and numeric/text/null distinctions without decoding into float64. Supported timestamp text uses the existing Python-compatible clock representation; malformed or unsupported-precision text remains raw. An actual old rounded fingerprint is seeded in PostgreSQL, then claim/completion deterministically recompute the exact convention while preserving prior JSON bytes. Python CaptureRepository readers bind IDs and consume lifecycle facts, not fingerprint equality; request_backfill creates an explicit new request/requeue, and MarketService reads status/finished clocks. No active reader/writer was found that oscillates conventions or rejects unchanged evidence by comparing the old digest. Generic Store fingerprint behavior for other collections is outside this slice.

## Retained mappings, raw values and absence reasons

These are concrete boundary reasons, not a general Go-any or legacy exemption:

- `Record` result JSON and nullable TimestampText preserve physical historical evidence. They are never accepted as a new live result without the named outcome path. SQL NULL and JSON null remain physically distinguishable; required-key absence is a separate refusal.
- `DecodeRecord`'s JSON-key membership map and physicalObject test maps operate on the exact26-key wire envelope to prove omission/null/duplicate behavior. They are wire codecs, not business records.
- `result.go` identity sets are associative duplicate-detection indexes. `obligations.go`'s token-ID→symbol map is an explicit configured identity index with validated values, not a record-shaped dictionary.
- `storedBackfillClock` receives the existing foreign Range scalar and admits only aware text/time.Time; nil is genuinely missing and every other type errors. No seconds/milliseconds/unit/zone guess is retained.
- `decodeReferenceTradeIdentity` receives that foreign scalar and admits actual nonempty text or exact native/JSON integers. Boolean/float/other shapes refuse; no guessed identity is constructed.
- `decodeCoverageMinutes` uses raw Range rows only at its inbound codec, validates aligned in-window buckets and actual boolean completion, rejects conflicting duplicate observations, then returns named coverage. Its minute-index map is associative observed data.
- `decodeCompletedKlineMinutes` retains nullable completion as genuinely unreported, never verified complete. Wrong types/conflicting observations error; its minute membership set is an index.
- `decodePre24Reference`/`decodePre24Trade` inspect the actual arbitrary JSON reference_points array/object edge. Missing/null reference points, unreported completion/last_trade/clock and observed incomplete points cannot provide a verified predecessor; wrong reported types error. Latest equivalent witnesses can agree; conflicting latest witnesses refuse rather than choose an arbitrary ID. A nullable ts_prec stays uncaptured. No witness becomes the explicit INCOMPLETE reference variant, distinct from a Range/read error.
- Test memStore raw maps preserve sparse/malformed retained documents and prior results, exercising the actual Store boundary and mutation acknowledgment. Newly produced results pass the real named serializer with UseNumber at this test persistence edge. Real PostgreSQL tests independently prove SQL behavior, NULL handling and rollback.
- General `copyRow`, repairWindows indexes, incompleteRuns raw rows, `Range` filters/results, Options registry dictionaries and unrelated point/repair writers remain separately OPEN. Their broader APIs are not presented as typed completion; only the named backfill command/result and its narrow inbound codecs are activated here.
