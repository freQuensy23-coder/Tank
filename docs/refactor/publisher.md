# Typed publisher qualification

The deployment publisher separates the trusted orchestrator commit from the selected Tank release. The current source uses named contracts and inward effect ports; the production CLI still fixes the API endpoint, refuses redirects and ignores ambient proxy configuration. Packaging executes the verified orchestrator archive and reads a real checkout of the selected commit. ## Durable build acceptance

`SubmissionFacts` requires the selected source digest, actual source release SHA, positive finite original budget and a `COLLECTION_ONLY` timestamp. An unavailable/regressing clock refuses. `UnknownBuildSubmission` deliberately has no guessed provider ID. It is written and fsynced before the POST; any unresolved acceptance refuses another submission. `ReceivedBuildSubmission` carries the actual admitted response ID and one of the provider's eight documented build states. It is persisted immediately after the response, before polling, provenance or cache work. Poll responses must retain that ID and are persisted before use.

A restarted process resumes only a received ID. Its remaining budget comes from the original collection clock/budget, not a fresh600seconds or a stored process-monotonic value. A late observed `SUCCEEDED` remains a success observation but cannot authorize activation at/after the deadline. A clock that moves backward refuses. The verified source cache is durable before the receipt is removed; interrupted cache/receipt cleanup therefore remains recoverable without another POST. A receipt may serve a different selected Tank SHA only through the existing verified same-source cache semantics: full source digest and actual build marker SHA must match the received submission. The build's real source SHA is retained.

`PublisherJournal.read_submission`, `write_submission` and `remove_submission` use a separate SHA256-keyed filename and the existing private-owner/mode, no-follow, atomic replacement and file/directory-fsync boundary. Missing journal files mean no recorded submission; omitted required JSON keys do not mean absence. Raw duplicate keys refuse before named projection. Abandoned temporary files remain evidence and are never searched for a guessed identity. Intent-write failure prevents POST; receipt-write interruption leaves the authoritative unknown intent and prevents a duplicate POST.

There is no exactly-once or remote-cancellation claim. The official build POST documents a tag applied on success and layer-cache controls; neither is a verified request-idempotency key. List order, timestamps, latest build and the deterministic release tag are not used to infer a lost response. Automatic UNKNOWN recovery is intentionally unavailable. The production bootstrap's single owned lease remains the concurrency authority.
