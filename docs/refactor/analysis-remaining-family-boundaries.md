# Remaining analysis family producer boundaries

Read-only source audit, 2026-10-26. This document is not an activation or test receipt. The audit uses the isolated recorded-USD branch at 0c9cfcc9 and compares the relevant production orchestration with parent 1519805b. Newer Spot ownership and Runtime caller candidates remain separate. No parent files were edited and no runtime qualifier was launched.

## Funding

The active selective `deriv.funding_vs_normal` branch in `analysis/truth.py:compute_condition_values` selects funding, instruments, semantics, capture metadata and capture tier, then invokes the full `derivatives_truth` calculator. That calculator also constructs OI, liquidation, basis and incremental-volume results. Those unrelated calculations are not required input facts for a funding-only result; their absence must become NOT_REQUESTED phases rather than synthetic records.

`derivatives_truth` groups the token's non-spot instruments from configured instruments and actual observations. For each instrument it selects the last settled row and last current-estimate row at or before cutoff. A calculable current estimate takes precedence; otherwise the settled rate supplies the comparison. The start witness is the last settled row at or before the interval start. The baseline uses settled rows strictly before start, positive captured interval hours and captured rates, with actual minimum history span and configured quantiles. Eight-hour normalization is a calculation unit, not a default assertion that the provider interval was eight hours. Current normalization receives `kind` and `interval_h` as required arguments and rejects nonpositive intervals.

Existing `ConditionFundingObservation`, `AvailableConditionFunding` and `UnavailableConditionFunding` already preserve settled, estimate and start observations, explicit selected kind, baseline and comparison. Their source observations retain clocks but do not themselves bind instrument identity, receipt visibility or canonical source evidence. Those facts belong in the strict consumed input/read projection and actual selector, with original bytes/descriptors retained separately. Do not turn a collection-only estimate clock into an exchange observation clock.

The current selective freshness loop chooses the latest raw funding row independently from the selected normalized comparison witness. A later unusable estimate can therefore supply a different clock from the settled row actually consumed. The typed replacement must assess the selected witness, preserve raw observations and failed freshness separately, and avoid refreshing a comparison using an unrelated row. This is a source-audit finding, not yet a demonstrated behavioral regression test.

A coherent next funding tranche is: strict storage-read admission and immutable evidence ownership; actual settled/estimate/start selection; required captured history policy; pure normalization and baseline calculation; typed per-instrument result; selected-witness freshness; actual wire serializer and cache adapter. It must cover missing rate, missing interval, known zero, unusable latest estimate, equal-clock ambiguity, future receipt, unchanged live reuse, changed eligible witness and all configured instrument membership. Funding-only must not require OI, liquidation or price facts.

## Reference close

`condition_reference_close` ranks eligible spot instruments by complete trailing-24-hour native flow volume. It then selects the latest positive complete candle close at an exact hour and requires its endpoint to equal the cutoff's expected completed hour. This is not an arbitrary latest-trade reference. Its `ref_venue` wire name currently carries the instrument ID; the existing serializer deliberately preserves that alias.

The source time comes from captured close-time metadata or an explicit open-time plus captured interval transformation. The current implementation uses a 60-second interval fallback for a retained row without `interval_s`; that fallback needs a documented collection/writer contract before strict admission may treat it as a fact. The `mkt.klines_1m` collection name alone must not silently supply missing source precision. The ranking flow calculation likewise needs the actual Spot policy, admitted flow inputs and source coverage, without admitting unrelated windows or revalidating the same full source repeatedly.

`_price_groups` reads stored native-quote `c`/`close`, without a USD conversion. `ObservedConditionClose` presently retains only instrument ID, positive Decimal price and observed Timestamp. It cannot alone prove USD currency or qualify a cross-currency threshold. A typed close producer must retain actual quote identity and preserve the declared threshold unit; USD conclusions require an actual qualified USD unit or historical rate evidence. No stablecoin parity or current-price fallback is authorized. This currency seam is shared with relative prices and must be coordinated with the existing quote valuation contracts before activation.

A coherent close tranche is: actual admitted per-instrument 24-hour flow ranking plus precise candle read projection; deterministic reference selection with ambiguity refusal; expected-hour test; captured/derived endpoint Timestamp; native denomination and actual threshold unit; strict result plus immutable evidence capability; cache identity from consumed content and visibility; fresh request assembly only in the wrapper. Preserve current stale-hour, missing-flow, receipt and no-live-write oracles.

## Remaining operational cache and consumers

The current top cache has eight family domains: spot, OI, funding, close, confidence, depth, state and relative. The nested state cache contains spot, relative, derivatives and supply nodes. The shared 128-entry FIFO budget and existing dependency, subject, interval, configuration and direction coordinates remain intentional. Content and visibility identities must reflect actual consumed projections; assembly is fresh request context, not an exact-clock cache key or a cached processing claim.

Typed output contracts and serializers are passive prerequisites, not proof that the actual producer can construct them. OI is currently closing selected endpoints, native versus recorded USD populations, exact recorded decomposition and synchronized cohort history. Funding and close remain active raw producers. Confidence/depth still need actual cadence/source and selected-book admission. Relative/liquidity need native versus USD qualification and actual historical FX evidence. Full state/supply require actual source adapters and requested/unrequested phase distinctions. Selective composition must retain independent direct freshness gates and prevent a full-state overlay from restoring a stale requested value.

The final cache annotation must be the precise union of actual named family facts and separately owned evidence capabilities after their production callers migrate. Annotating the current dictionaries as JsonValue/object/Any, or validating the whole serialized result as a facade, does not close this boundary.

`Scheduler.condition_truth` still probes `condition_values` with getattr/callable and falls back to `assess` for alternate objects. `metric_value` still walks raw nested maps, supports both historical derivative-pack layouts and uses a generic field fallback. `funding_state` requires a nonempty complete per-instrument comparison set, then returns ABOVE if any above, BELOW if all below, otherwise WITHIN. Its replacement must consume the actual closed selective result and requested metric scope; it must not infer completeness from a partial list. The canonical typed service port is not yet activation-ready, so removing that fallback requires a coordinated Scheduler caller cohort rather than a parallel Truth facade.
