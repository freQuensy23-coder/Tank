## Typed boundary and absence ledger

- `Context`, `Run`, `MatrixJob`, `Artifact` and `Receipt` validate consumed identity/status facts. GitHub API records allow unconsumed extension fields; arbitrary JSON stays at the raw HTTP/event admission boundary and duplicate keys refuse before projection.
- `OtherJob` consumes only a nonselected job's name. It explicitly refuses all three selected names, so malformed matrix metadata cannot escape through that union branch.
- `MatrixJob.conclusion` is required but nullable while unfinished. Only completed/success is admitted to `SuccessfulJob`; missing fields and unfinished terminal conclusions refuse.
- `Artifact.workflow_run` is required but may be null in raw API input. Selected `UsableArtifact` requires it, positive size and actual boolean false for expiry. Null or absent provenance cannot authorize a download.
- Name-to-job/artifact dictionaries are associative indexes over admitted records, with duplicate refusal before insertion. Environment mappings, HTTP headers and argparse mappings remain native boundary representations; arguments enter named strict phase models before use.
- `SignalState.received=None` means no signal has occurred; it is not an execution-success substitute. `SetupReport` requires all three named children and zero exit codes for success. Native Popen/log handles stay native typed resource handles.
- The polling sleep and monotonic clock defaults are the actual runtime operations; injection exists only for deterministic admission/deadline controls. Polling never turns an API error into success or invents an absent fact.
