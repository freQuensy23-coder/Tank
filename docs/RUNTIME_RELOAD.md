# Configuration snapshots and SIGHUP

`tank serve` handles SIGHUP as a supervised configuration reload. Configuration bytes are captured, parsed and fingerprinted before a replacement generation is constructed. The running generation keeps its immutable snapshot while the candidate is checked. A malformed or invalid candidate is logged and rejected; the existing service continues with its existing version. Configuration and process code versions are derived automatically, so operator environment files must not supply placeholder commit strings.

After a valid candidate is prepared, the runtime stops source and scheduler intake. The eight workers, market capture and session streams continue while due jobs and active session work drain. This lets an old-version agent tool finish its queued market dependencies before cutover. The drain is bounded by `TANK_SHUTDOWN_GRACE_S` (30 seconds by default). At the bound, unfinished work remains durable for recovery; the previous components are closed before new components start. Existing OpenMA session IDs and cursors are resumed, and completed tool results are reused. Session model/prompt provenance is distinct from the configuration version used by each derived tool output.

The supervisor rejects changes to the Tank database connection, OpenMA endpoint or data root during SIGHUP; those require an explicit process restart. Changes to Python code also require a restart: the code fingerprint is pinned when the process first resolves its configuration. Accepted configuration snapshots are retained under `data/config_versions/` and included in the complete backup.

In the Linux deployment, run `docker compose kill -s HUP tank` after finishing the complete read-only-mounted configuration edit. Do not send TERM/INT when requesting a reload; those perform the same orderly shutdown and then stop the service. Inspect the reload log for the accepted configuration version or the explicit rejection. A failed candidate must be corrected before another SIGHUP; no fallback thresholds are substituted.

Manual backups use `tank backup --force` through `deploy/backup.sh`. Set `TANK_BACKUP_DIR` to the mounted external backup directory and `TANK_LOGS_DIR` to the permanent service log directory. `--force` bypasses the backup-hour guard, while manual retention remains an explicit `--prune` option after full verification. The daily heartbeat includes both queue lag and queued/running analysis backlog.

The required subscription gateway listens on the Compose network at port 8790 inside the same `tank serve` asyncio process. It is started before source/session work and stays available during the drain, then closes before the replacement generation binds its listener. Gateway preflight validates the configured internal key and sign-in file before a candidate can replace the live generation; it performs no upstream model call. Docker Compose contains exactly Tank, OpenMA and PostgreSQL. Token/spending caps and budget-pause admission are outside V0 scope. Doctor reports internal-key configuration and sign-in-file presence without printing secrets or reading the sign-in contents.
