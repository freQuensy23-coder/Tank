## Operational requirements and limits

Provision OpenMA and exact deployed agent/environment IDs in config/openma.yaml; set API keys via environment/secret manager. Scout uses a separate deployed reviewer agent, allowlisted callbacks, and proposal identity. The environment's database credentials/role restriction must be provisioned by deployment; Python callback checks are additional isolation, not a substitute for database privileges. Replay requires a fresh replay_run_id and replay_environment_id with network disabled. External web_search/fetch_page responses come from unambiguous captures; event, market and verdict tools execute code again. Missing captures return an explicit tool refusal, and uncached Jev calls are prohibited.

Explicit first-reference fixture reconstruction uses preregistered authored item messages, not invented historical session logs. Its real publication tools may generate immutable cards and delivery intents. Those `DELIVER` jobs remain `QUEUED` unchanged and are exported with `delivery_status=NOT_RUN` and `delivery_reason=FIRST_REFERENCE_NO_CAPTURED_DELIVERY`; they do not block settled analysis completion. No delivery transport runs, no `SENT` receipt or message reference is manufactured, and no call opens or clock advances through delivery. This completion proves the generated analysis/publication scope only. Ordinary historical replay still requires original publication lineage and a captured `SENT` receipt for each replayed delivery transition.

Calibrate and record filter_cutoff/routing_cutoff before model decisions that need them; an official item without real event candidates can open a session without a routing score. Mock HTTP/SSE tests prove adapter behavior, not account access or hosted model availability. Offline tests make no paid calls. A separately authorized live verification scored two public synthetic examples through the original SDK/OpenRouter endpoint (`docs/verification/live-openrouter-jev-2026-10-18.json`). The subsequent plain-HTTP adapter and specified chat endpoint diagnostic are separately recorded in `docs/verification/live-openrouter-http-jev-2026-10-18.json`. Token and spending limits are outside V0 scope. Paid or unknown Jev usage never blocks agent messages; source/work priorities remain in effect. Provider errors reach OpenMA, whose generic turn error retry runs once.

The event POST's idempotency survives a lost reply. Tool DONE is committed with the tool mutation before posting its result, so a retry reuses the result. Slow get_market_truth dispatch commits its durable jobs outside that transaction so workers can complete them. After the one resend, a repeated agent failure marks the session FAILED with its terminal failure (03 §3.2); EventLifecycle has no FAILED, so the event record is unchanged and the event is no longer open. No card is synthesized from an agent failure.

Terminal session cleanup waits for an observed end-turn idle state, no open calls, no unfinished tools, and no queued/running event work. An invalidated event that previously published a card additionally requires delivery's explicit finalization marker and a SENT safety UPDATE. An invalidated event that never published a card may end when idle with no calls/work; it has no audience correction obligation.

Routing (03 §3.1) offers as candidates only events whose session received an item within routing_window_days and that share an entity or token with the item; an event whose session is FAILED is not open and is never a candidate. Without a candidate at or above the calibrated cutoff the item opens a new session. Recent candidates use keyset time-range scans; sessions are resolved through scoped keyset identifiers without permanent-history caps.

After configuration reload, host tools execute the adopted immutable runtime snapshot. Each callback includes the originating session's saved model, prompt and deployed agent version, plus `session_config_version` and `session_code_version`; top-level `config_version`/`code_version` describe the actual host execution. OpenMA agent versions absent from the remote response/config remain unknown rather than being inferred from the prompt name. Agent tokens are accounting observations under SUBSCRIPTION billing, not a dollar admission policy. Configuration snapshots are persisted centrally by Settings for reproduction, not duplicated in sessions.

`get_market_truth` sends a deterministic wire projection of the full durable tool result: only each MTA record's redundant top-level `measurement_metadata` companion is omitted. Canonical values, windows, venue rows, confidence, evidence, inline measurement context, and any similarly named nested evidence fields remain exact. The wire response carries omitted JSON pointers, `ana.market_truth` MTA IDs with parameterized read-only SQL for the companion, and the session/call reference and query for the full `ops.tool_calls` result. No size cutoff or truncation applies to domain fields. Lost-response recovery projects the saved full result identically without executing the tool again; evidence bundles retain the full authoritative MTA.


At most `max_running_sessions` (config/openma.yaml, default 2) sessions run a turn at once. A message to a new or idle session beyond the cap waits as its QUEUED job without spending an attempt or changing its expiry, ordered by priority and first enqueue; the sessions loop wakes the oldest waiting turns when a slot frees. A message to a session already running is never held back.

Tool validation refusals roll mutations back, persist REFUSED and answer the agent with a safe reason and is_error; an unavailable provider/transport remains a recoverable failure. Credential-bearing argument URLs are refused and redacted before the host tool ledger or dispatch. Message retries identify the active durable turn rather than the newest queued message, with one retry counter per turn. Idle sessions stop their SSE task and resume on new input; a completed NO_EVENT session is archived after end-turn idle.

Jev score cache identity includes the exact named wire question (instructions and criteria), pinned model, prompt version, and canonical state fingerprint. Usage records retain the full question and state/question/request fingerprints. Legacy entries lacking that identity are preserved but cannot satisfy a new request; literal prompt changes trigger a fresh provider call, while identical requests reuse their existing score without another paid call.

F24's explicitly declared synthetic two-phase reference retains the original post+1-minute `cutoff_instant` as its initial evaluation boundary. Its optional input-only `phases` list binds two ordered message coordinates, with the packet `cutoff` serving as the final observation horizon. The same fresh native session continues after each committed turn. Host-only immutable phase checkpoints preserve actual outputs and callback/completion proofs; they are never supplied as semantic inputs. At a settled phase boundary the host retires its old SSE follower before advancing the prefix and submitting the next item, preserving the native session/workspace. Future source rows, reference captures and market requests remain unavailable until the simulated phase clock reaches them. A declared empty official lookup expires when the later confirmation phase begins; missing eligible captures are refused without clock advancement.

Minute-only fixture literals may explicitly select `UTC_MINUTE_END_EXCLUSIVE` as a separately preregistered reference convention: observe the whole named UTC minute, retain the original `BUCKET(1m)` call precision and literal, and select its upper boundary without claiming an exact historical call instant. Point observations at that exclusive endpoint are excluded; completed bars ending there remain eligible. This policy is uniform across minute-only reference fixtures, never a selective F22 source backdate. Prior `MINUTE_START` generations and ordinary AS_OF replay retain their declared semantics. Generated reference UPDATE lineage is evidence of publication intent only; without delivery transport it is not a proof of a threaded Telegram send.
