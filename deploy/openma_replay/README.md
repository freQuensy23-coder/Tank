# Sealed replay evidence boundary

`replay-evidence.ts` is copied into the pinned OpenMA adapter by guarded source preparation. It validates the dedicated controller evidence root, the selected run child, exact manifest SHA, native session run/cutoff metadata and every flat content-addressed file's length/hash. Symlinks, traversal, unlisted files and unexpected manifest payload fields are refused before a VM is constructed. The guest volume is only that run child at `/replay/evidence`, read-only. Other prepared runs and host-only audit receipts stay outside its mount.

Tank writes only prepared replay artifacts to the dedicated `sealed-replay-evidence` volume at `/data/replay/evidence`; the trusted OpenMA controller sees it read-only at `/app/replay-evidence`. Neither the live Tank data tree nor evaluator outcomes are mounted. The normal replay command initially publishes only the first-message prefix, then advances the same guest directory with ReplayClock before each later message/tool. Immutable full inputs and per-prefix generations stay outside the controller volume. Native manifest hash/cutoff metadata is updated before dispatch; transient mismatch is refused. Mutable prefix hash/cutoff are not static guest environment or allocation fingerprint fields, so advancing the view does not recreate a session/VM. The command creates a fresh logical replay session; this does not add an operator approval or manual per-run restart gate.

Required native metadata is `tank_replay_run_id`, `tank_replay_evidence_sha256` and `tank_replay_cutoff`, matching `manifest.json`. The sealer owns cutoff filtering and source-proven coverage; the Node boundary verifies the sealed contract and bytes rather than reinterpreting the JSONL prints or guessing timestamp precision. Unknown precision remains null with its explicit reason. Guest scripts use the explicit relocation map, never a live-directory glob or original host path.

Filesystem refusal tests run with Node24 using `node --test replay-evidence.test.mjs`. Their fixture bytes deliberately test filesystem binding, not JSONL validity. Actual sealer/verified-reader contract tests and real VM read-only/run-isolation checks are separate gates. No native VM or production deployment is certified by these unit tests.

A controller/OpenMA restart during a still-running host replay must revalidate the current published prefix and preserve the logical session and workspace. This does not promise recovery of an interrupted host CLI process: a new CLI invocation uses a fresh isolated run/database. Publication interrupted between filesystem commit and native metadata update is incomplete and fails closed; its receipts are preserved rather than silently restarting at time zero.
